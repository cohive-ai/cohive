## 一、接口

- `POST /api/v1/me/display-name`，请求体 `{"display_name": "..."}`，成功返回 `{"display_name": "清理后的值"}`。
- **只认网页会话**：密码登录和 cohive web 免密登录都可以。
- **编程工具令牌一律拒绝**：返回 403，错误码 `web_only`，沿用现有的“仅限网页”判定。设备密钥同样被拒。
- 只能改本人：接口不收账号参数，直接取当前登录的账号。登录名不变。
- 已归入“必须留记录的网页写接口”清单（`audit_entry_test.go`）。以后谁把它挪出清单，或者让它不再记录，测试会变红。

## 二、校验与防冒充

- 先用 `cleanDisplayName` 清理：去掉首尾空白，最多保留 64 个字符。
- **新增：不可见字符一律拒绝**。显示名含控制字符或不可见的格式字符时，按参数错误拒绝（400，`invalid_input`）。
  - 格式字符包括零宽空格、零宽连接符、从右到左覆盖符等。
  - 原因：不拦的话，`lee​-codex` 这种写法能绕过撞名比较，但在群消息里看起来和 `lee-codex` 一模一样；从右到左覆盖符还能把显示顺序倒过来。
  - 代价：含零宽连接符的组合表情（例如“一家人”表情）不能用。只影响本人修改这条路径；管理员命令行和注册不受影响。
- **撞名检查**：新显示名不能和本人所在的任一工作空间里其他在册成员的登录名或显示名相同。
  - 比较时不区分大小写，忽略首尾空白。
  - 已移出的成员、已停用的账号、不在同一个工作空间的人都不算。
  - 用自己的登录名做显示名是允许的。
  - 撞名时返回 409，带两个字段：
    - `code: "display_name_taken"`；
    - `clash: "name"` 或 `"display_name"`，表示撞的是别人的登录名还是显示名。
  - 报错文字有中英两套，**只说撞的类型，不说撞的是谁**。理由：说出是谁没有帮助，反而让人可以拿它试探别的工作空间里有哪些人。
- **并发**：两个人同时改成同一个名字时，靠一把全局的事务级咨询锁让本人改名排队，保证不会两个人都通过检查。本人改名很少发生，排队的代价可以忽略。
- **原样保存**：新值和现有值相同时，什么都不做，也不记录。
  - 所以如果某人当前的显示名本来就撞名（比如历史数据，或者他后来加入了另一个工作空间），原样保存不会报错，换一个新名字时才检查。

## 三、清空

- 传空串，或者全是空白，就清空显示名。
- 清空后，各处都按现有“没有显示名”的逻辑显示登录名：页头、看板、成员列表，以及群消息里的“登录名（显示名）”写法。
- 清空同样记一条操作记录，内容是“从某某改成空”。

## 四、操作记录

- 和管理员改显示名用的是同一种记录：动作都是 `account.update`，附加信息里都有 `display_name: {from, to}`，“原来 / 改为”的展示和管理员那条一样。
- 本人改的这条：
  - 入口记为网页，操作人是本人，对象也是本人；
  - 附加信息多一个 `self: true`，不在详情里单独显示；
  - 记录文字写成“修改了自己的显示名”，英文是“updated their own profile: Display name”。
- **不挂在任何工作空间下**，和本人改密码一样，属于服务器级记录。
  - 结果：服务器管理员在操作记录页能看到；工作空间管理员在本空间的记录页**看不到**。
  - 这是我按现有分类做的取舍，见第九节第 1 条，你可以改。

## 五、前端

- 个人中心“基本信息”的显示名旁边加了“修改”。
  - 点开后是输入框，占位提示是“留空则显示登录名 xxx”，下面一行说明“不能和其他成员的登录名或显示名相同”。另有“保存”和“取消”。
- 保存成功后，提示“显示名已保存。”；清空时提示“显示名已清空，各处将显示登录名 xxx。”。
- 撞名或其他失败时，留在编辑状态，显示服务器按界面语言返回的报错。
- 保存后会刷新这些缓存：本人信息、看板、问题单列表与详情、管理页（含成员列表）、服务器账号列表、操作记录。不需要整页刷新，页头和看板会立刻换成新名字。
- 中英文案都补齐了。网页测试覆盖了中文的完整流程（撞名、保存、清空、刷新缓存），以及英文文案和“取消不提交”。

## 六、同步复核（没有改代码）

- 按名字找人（`cohive_find_member`）、指派时识别名字、群通知、审批消息、会话提醒取成员名字，都走 `store` 的 `memberColumns` / `accountColumns`。这两处每次查询都直接联表读 `accounts.display_name`，**没有任何缓存**，所以改完立刻生效。

## 八、测试服实测步骤（合入、部署之后）

准备：工作空间里至少要有两个人，下面用 A（本人）和 B（同空间的另一位成员）指代。B 要有登录名，最好也设了显示名。

1. **改名**：A 用密码登录，打开个人中心，点显示名旁的“修改”，改成一个新名字，保存。
   - 应看到“显示名已保存。”；
   - 页头右上角立刻变成新名字，不用刷新；
   - 切到看板，自己那一栏的名字也是新的。
2. **冒充登录名**：再点“修改”，填 B 的登录名，故意换一下大小写、前后加空格，保存。
   - 应提示“和另一位成员的登录名相同”，报错里不出现 B 的名字；
   - 浏览器开发者工具里能看到响应是 409，`code` 为 `display_name_taken`，`clash` 为 `name`。
3. **冒充显示名**：填 B 的显示名（换大小写）。应提示“和另一位成员的显示名相同”，`clash` 为 `display_name`。
4. **清空**：把输入框清空后保存。
   - 应提示已清空、将显示登录名；
   - 页头、看板改为显示 A 的登录名。
5. **免密登录也能改**：在 A 已配对的电脑上执行 `cohive web` 打开网页，在个人中心再改一次名，应能成功。
6. **令牌被拒**：用 A 的编程工具令牌直接调接口：

   ```bash
   curl -s -X POST -H "Authorization: Bearer <A 的令牌>" -H "Content-Type: application/json" -d '{"display_name":"x"}' https://<测试服>/api/v1/me/display-name
   ```

   - 应返回 403，`code` 为 `web_only`；
   - 回到个人中心确认名字没变。
7. **操作记录**：服务器管理员打开服务器级的操作记录页。
   - 应能看到 A 的几条“修改了自己的显示名”，入口是网页；
   - 展开后能看到“原来 / 改为”。
8. **同步**：A 改成一个新名字后，让 B 在编程工具里用这个新名字调 `cohive_find_member`，应立刻找到 A。
   - 有条件的话，再触发一条和 A 有关的群通知（例如给 A 派单），确认群里显示的是“A 的登录名（新显示名）”。

## 九、需要你定的事

1. **工作空间管理员要不要也能看到这条记录？** 现在只有服务器管理员能看到（和本人改密码一样）。
   - 想让各空间管理员都能察觉冒充：可以改成本人在册的每个工作空间各记一条。代价是服务器级的记录页会出现重复。
   - 我的建议：先维持现状。小团队里服务器管理员通常就是负责人，再加上群消息里登录名一直可见，够用。
2. **另外两条改名路径不做撞名检查**，本次也没动：
   - 管理员在命令行改显示名，以及注册时自己填的显示名，都不检查撞名；
   - 某人加入新的工作空间时，也不会检查他现有的显示名和那边的人撞不撞。
   - 建议：注册时也加撞名检查，另开一张单；管理员那条路径维持不查，理由是管理员可信。
3. **形近字没拦**。比如西里尔字母的 а 冒充拉丁字母的 a，现在拦不住，要拦得引入 Unicode 混淆字表。
   - 建议暂不做：群消息里登录名一直可见，登录名本身只允许小写字母、数字、下划线和连字符。

- **并发用例** `TestSetMyDisplayNameConcurrent`：用真实数据库，让两个账号同时把显示名改成同一个值。

  - 要求：只能一个成功，另一个拿到 `display_name_taken`，库里只有一个人叫这个名字。
  - 删掉全局锁 `LockDisplayNames` 后，用例连跑 3 次，3 次都变红，报“成功 2，撞名 0”。保留锁时连跑 20 次，全部通过。
