## 一、主题文件

- 外观变量（27 个：22 个颜色、1 个半透明遮罩色、2 个圆角、2 个阴影）全部从 `styles.css` 移到 **`web/src/theme.css`**，`styles.css` 只剩 Tailwind 映射和少量全局样式。
- 新增两处 `color-scheme`：手动选浅色或深色时，表单控件、滚动条也跟着换。
- 组件里不写死颜色：UI-1 的主题守卫照旧，组件里出现十六进制色、调色板色、写死的阴影或圆角都会报错。

**规则只有一份**：`web/theme-spec.json`。里面是变量清单（名字、类型、中英用途）、文字 4.5 / 图形 3 的门槛、29 组文字对比和 4 组图形对比。

- 网页的 `contrast.test.ts` 和服务端的 `internal/theme`（检查命令、加载时的报告）读的都是它；Go 端通过 `web` 包嵌入。
- 另有 **`web/theme-cases.json`**：8 组颜色覆盖，每组写明应当不达标的检查项。期望结果用第三方脚本按 WCAG 公式算出。网页测试和 Go 测试各自跑一遍，必须报出完全相同的清单。两边任何一处阈值、配对、层叠写得不一致，都会变红（见探针 P2、P13）。
- 两边都检查“规则清单与 `theme.css` 定义的变量一一对应”，新增变量忘了登记会红。

## 二、服务器加载自定义主题

- **从哪里读**，只能由服务器管理员放，网页上没有上传入口：
  1. `COHIVE_THEME_FILE` 指定的文件；指定了却读不到，或者不是普通文件，**拒绝启动**；
  2. 没设时用数据目录下的 `theme.css`（Docker 是 `/data/theme.css`），有才用。
- **过滤**：`internal/theme` 逐条解析。
  - 只接受 `:root`、`[data-theme="light"]`、`:root[data-theme="dark"]`、`[data-theme="dark"]` 几种块（引号可省），块里只接受 `--名字: 值;`。
  - 名字必须在变量清单里，取值按类型白名单检查：颜色只认 `#rgb` / `#rrggbb`，遮罩色另认 `#rrggbbaa`、`rgb()`、`rgba()`，长度只认 0 或带 px、rem、em 的数，阴影只认 `none` 或最多两组“长度 + 颜色”（颜色可写 `var(--颜色变量)`）。
  - 另有一道一律拒绝的清单（不论变量类型）：`url(`、`image(`、`image-set(`、`expression(`、`javascript:`、`attr(`、`env(`、`@`、反斜杠、尖括号、引号、反引号、花括号、分号、`!`、注释符、控制字符。
  - 非变量属性、其他选择器、任何 @ 规则（含 `@import`、`@media`）、块里套块、未闭合注释，都算被拒绝。
  - 超过 64 KB 不读：只读 64 KB + 1 字节，判为文件过大；非 UTF-8 也拒绝。
- **加载策略**：
  - 有任何一处被拒绝的写法，整份不加载，照常启动、用默认主题，启动日志写明原因并提示用检查命令；
  - 未知变量丢掉并在日志里提醒；
  - 对比度不达标照样加载，日志提醒，由管理员决定。
- **不转发原文**：服务端用过滤后的取值重新生成样式表。
  - 浅色写进 `:root`；深色同时写进“跟随系统”的媒体查询块和 `:root[data-theme="dark"]`，管理员只需写一次深色。
  - 生成结果以 `/theme.css?v=内容哈希` 提供，类型 `text/css`，带 `nosniff`。
  - 入口页在 `</head>` 前、Vite 生成的默认样式链接之后插入这一行，选择器优先级与默认主题相同，靠顺序覆盖。
- **没有自定义文件时，行为与现在完全一致**：不注册 `/theme.css`（访问它会照旧落到前端路由），入口页一个字节不变。有测试逐字节比对。

## 三、个人中心的深浅切换

- 个人中心新增“外观”：跟随系统（默认）、浅色、深色。
- **存在本机浏览器（`localStorage`），不存账号**，理由：
  1. 深浅是设备和环境相关的偏好：白天办公室显示器、晚上笔记本可以不同；跟随系统本身也是按设备的。
  2. 要在页面绘制前就套上，才能避免闪烁，连登录页也要生效；存账号就得先请求接口，必然先闪一下默认颜色。
  3. 服务端没有任何地方用得到它；语言存在账号上，是因为群通知、编程工具、命令行都要用，这一项没有。
  4. 不用改数据库和接口。代价是换电脑要重选一次，可以接受。
- **实现**：
  - `web/src/theme.ts` 负责读写，写到 `<html data-theme>`；
  - `index.html` 里有一段同逻辑的小脚本，在绘制前先套上；`main.tsx` 里再套一次，防止那段脚本被拦。
  - 有测试直接执行入口页里那段脚本，确认它和 `theme.ts` 读同一个键、只认 light 和 dark。
- 走查确认：系统为浅色时手动选深色，整页刷新后仍是深色（见第三张截图）。浏览器里的选择已经复原。

## 五、检查命令

`cohive-server theme check [文件]`：

- 不给文件时检查内置默认主题。
- 报告分三段：被拒绝的写法（行号、变量、原因）、未知变量（行号、名字）、浅色和深色两种主题下每组对比度（实测值、门槛、用途，不达标标 `FAIL`）。
- 文案中英两套，跟随命令行语言。
- 退出码：0 全部通过；1 有被拒绝、未知或对比度不达标（只有未知变量也算 1，多半是拼错）；2 用法不对或文件读不到。为此主程序加了按错误类型取退出码。
- 命令帮助、环境变量说明（`COHIVE_THEME_FILE`）两种语言都补了；命令归类守卫里登记为只读命令。

示例输出（节选）：

```
主题文件：bad.css

被拒绝的写法（改掉之前服务器不会加载这份文件）：
  第 1 行  --bg：取值里不允许出现“url(”
  第 1 行  color：只允许写 CSS 变量（--名字: 值）
  第 2 行  @import "x.css"：不允许 @import、@media 这类 @ 规则

未知变量（加载时会被忽略）：
  第 1 行  --brand-blue

对比度，浅色主题：
  FAIL  2.13  文字 --muted 在 --bg 上，要求 4.5
  …
结果：3 处被拒绝，1 个未知变量，3 组对比度不达标
```
