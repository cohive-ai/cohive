## 方案要点

1. **选库**：网页用 i18next + react-i18next；Go 用 go-i18n v2（v2.6.1，仍在维护，Weblate 原生支持其 JSON 格式）。自写加载器、x/text gotext 两个备选方案的比较见方案 4.1。
2. **文件**：`locales/<语言>/` 分目录。Go 用扁平点分键，按区域分文件（cli、server、mcp、issue、secretscan，第二段加 notify）；网页用 i18next v4 JSON，按命名空间分文件。分文件既方便翻译平台导入，也减少与在飞分支、子代理之间的冲突。
3. **语言决定**：与主脑初步建议一致，补充一处（方案 3.3）：**账号语言作为唯一的个人设置**，网页、命令行、MCP、会话钩子都以它为准，注册时记录当时的界面语言。原因是很多中文开发者的终端是 `LANG=en_US`，“命令行跟随系统”会让 lee 团队的命令行变成英文；MCP 也没有客户端信号。系统语言、浏览器语言只在还不知道是谁时使用；`COHIVE_LANG` 可以临时覆盖。
4. **缺省与回退**：服务器缺省语言用 `COHIVE_DEFAULT_LANGUAGE`，不设时为英文；缺词回退英文。**测试服合入后必须加 `COHIVE_DEFAULT_LANGUAGE=zh-CN`**，否则群通知和 MCP 会变英文。
5. **报错**：新增可本地化的错误类型，httpapi、mcpserver 在出口统一翻译；第一段先接好出口，core 的中文报错要到第二段改成键才生效。接口错误加稳定的 `code` 字段。
6. **测试**：中英键必须齐全、各语言占位符一致、代码里用到的键都存在；另加一个防回潮守卫（非测试源码注释外出现中文即失败，第一段对四个禁区带白名单）。现有约 2300 行断言中文的测试固定用中文跑，每个出口另补英文用例。
7. **社区规范**：CONTRIBUTING 中英版、行为准则（Contributor Covenant 2.1）、SECURITY（私密漏洞报告）、议题与合并请求模板、发布说明分类、语言维护者登记表、给 lee 的维护者手册；另建议补 **GitHub Actions 持续集成**（仓库目前没有，外部合并请求无法自动验证）。不要 CLA、DCO；鸣谢用 contrib.rocks 头像墙加自动发布说明。
8. **分工**：框架、示范改造、审核由我做；抽取与翻译按区域分 6 个 sonnet 子代理（文件互不重叠）。
