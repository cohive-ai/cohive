## 做了什么

1. **第十三号迁移 `0013_language.sql`**：
   - 加了三列，都可为空：`accounts.language`、`workspaces.language`、`signups.language`（注册申请记下当时的界面语言，获批建账号时写入）。空表示跟随服务器缺省语言。
   - 已有的行一律留空，不批量写入。
   - **在测试服库上是否安全**：只加可为空、无默认值的列，PostgreSQL 只改系统目录，不重写表。CHECK 约束（只允许语言代码的字符与长度）会扫一遍现有行，几张小表是毫秒级，可以直接在有数据的库上执行。有迁移测试覆盖“旧行保持为空”和“非语言代码被拒”。
2. **账号语言（个人设置）**：
   - **网页**：
     - 个人中心“语言”一节改为存到账号（`POST /api/v1/me/language`），选项是“未设置”加各语言。未设置时，网页跟随浏览器，编程工具和命令行用服务器缺省语言。
     - 登录后读到 `/me`，账号设了语言就切换界面语言。
     - 登录页、注册页的语言切换仍只改本机。
     - 注册时把界面语言带给服务端，写到新账号上。
   - **接口**：
     - 请求带 `Accept-Language` 时以它为准（网页总会带）。
     - 不带时按账号语言，没设时用服务器缺省语言，并在 `Content-Language` 里回告。
     - `/me` 返回账号语言、服务器缺省语言和可选语言。
   - **MCP**：按令牌所属账号的语言选那一份服务，工具说明、参数说明、报错、状态名都跟着变。没设时用服务器缺省语言。
   - **成员命令行与会话钩子**：
     - 语言顺序：`COHIVE_LANG` > 账号语言 > 系统语言 > 英文。
     - 带凭据的请求不发语言头，服务器按账号回告，命令行把它缓存在配置目录的 `language` 文件里，不碰凭据文件，下次启动生效。
     - 网页上改了账号语言，命令行下一次访问服务器后跟上。
   - **真机验证过**：登录前按系统语言（英文）；登录后缓存服务器回告的中文（账号未设、服务器缺省是中文）；在接口改成英文后，下一次钩子检查之后变英文；`COHIVE_LANG` 始终优先。
3. **工作空间语言（群消息语言）**：
   - Admin 页“工作空间”设置里加了“群消息语言”，选项是“跟随服务器缺省”加各语言。运维命令行加了 `cohive-server workspace set --name <路径> --language <代码>`，空串表示跟随缺省。
   - 修改记入管理操作记录。
4. **群通知与机器人**（internal/notify）：
   - **群里**的问题单通知、接单、关单、超时催办、审批卡片和结果、群里指令的回复，都按该群所属工作空间的语言。同一条设备申请发到一英一中两个群时，各按各的语言。
   - **私聊**按收件人的账号语言。
   - **不知道对应哪个工作空间或账号时**用服务器缺省语言。
   - 待发记录存的是事件，发送时才渲染，所以改了工作空间语言后，积压的通知按新语言发出。
   - 钉钉机器人中文、英文指令都认，例如“绑定群”与 `bindgroup`、“群编号”与 `chatid`。
5. **业务层报错与文案**（internal/core）：
   - 全部报错只存文案键和参数，在出口（接口、MCP、命令行、机器人回复）按调用方的语言渲染。
   - 哨兵错误改成可本地化，`errors.Is` 照旧可用。
   - 看板与列表的“等谁处理”、会话钩子摘要按请求语言出。
   - 存进数据库的少量文字用服务器缺省语言，例如初始管理员显示名、重开升级原因。
6. **管理操作记录**：动作名、入口名、类别名、描述句、附加信息名都改为展示时按语言渲染。网页“记录”页随界面语言变化，运维命令行 `audit list` 用命令行语言。顺带补上了入口筛选里漏掉的“钉钉群”。
7. **数据层**：`store` 的哨兵错误（记录不存在、令牌无效、账号已停用等）可本地化；SQL 字符串里的中文注释移到了 Go 注释。

   - `issue.TransitionError.Error()` 改为用缺省语言渲染。
   - 防硬编码中文的守卫测试白名单已清空，Go 与网页都对全部源码生效。

## 合入后会变的地方（请主脑留意）

1. **测试服**：迁移只加空列，现有账号与工作空间都跟随 `COHIVE_DEFAULT_LANGUAGE=zh-CN`，群通知、MCP、命令行都仍是中文。第一段里“终端是 `LANG=en_US` 的成员命令行变英文”的过渡问题也随之消失：命令行第一次访问服务器后，会缓存服务器回告的语言（中文）。
2. **反过来的情况**：终端是英文、服务器缺省是中文、账号没设语言的成员，命令行登录后会从英文变成中文。这是“账号语言优先、没设时跟随服务器缺省”的规则，与 MCP 一致；想要英文就在个人中心设语言或设 `COHIVE_LANG`。主脑若想改成“账号没设时命令行跟随系统语言”，只需服务端在账号没设语言时不回写 Content-Language，改动很小。
3. **渠道底层报错一律英文**（Telegram、钉钉接口报错、额度、权限、凭据失效等），会出现在待发记录的失败原因和渠道状态里。管理员页面的渠道状态说明，可能是“英文报错 + 按缺省语言的配置提示”的混合。
4. **库里已有的旧中文文字不会改**：已写入的失败原因、旧管理记录里的名字快照等。新写入的按服务器缺省语言。
5. **管理操作记录的入口筛选**多了“钉钉群”。
6. **英文文档去掉了中文括注**：界面名称与英文界面统一（如 Admin → Pending、Audit log）。
