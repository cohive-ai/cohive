## 做了什么

### 1. Slack 通道（`internal/notify/slack*.go`）

- **Socket 模式长连接**：自己实现，结构与钉钉 Stream 相同。
  - 握手顺序：先用机器人令牌调 `auth.test` 查自己的用户编号和工作区；再用应用级令牌换连接地址；收到 hello 才算在线。
  - 每条推送先回确认，再处理。
  - 重连：断线后按 3 秒起、最长 1 分钟退避；Slack 定期要求换连接时马上重连，不算掉线。
  - 应用关了 Socket 模式（`link_disabled`）时离线，并写明原因。
  - 随服务停止而结束。
  - 日志、错误、状态里都不带一次性票据和令牌，测试里专门检查了。
- **群通知**：用一段 mrkdwn 消息块，`text` 字段放同样的全文，作为通知摘要。
  - @ 人写 `<@用户编号>`；没连接 Slack 的人只写名字。
  - 用户输入只转义 `&`、`<`、`>`，拼不出 `<!channel>` 或假的 @。
- **审批按钮**：消息块里带“批准 / 拒绝”两个按钮，按钮数据是 `种类:工作空间:编号:y/n`（和 Telegram 一样只用来核对）。
  - 点击走现有的 `Hub.Click`。点击者身份取 Slack 填写的 `user.id` 和 `user.team_id`。
  - 改成结果用 `chat.update`。
  - 没改成结果时（没权限、对不上、已处理），用只给点击者看的临时消息提示，因为 Slack 没有弹出提示。
  - 发消息时 Socket 模式不在线，就不带按钮，提示去网页处理；仍记下消息编号，别处处理后照样回写结果。
- **跨工作区的外部用户**：点按钮、在频道里 @机器人、私聊发码，一律回复“你不在这个 Slack 工作区里”，不碰业务层。判断依据是点击者或发消息者的工作区和机器人所在工作区不同。
- **收件**：接 IM2-0 的 `Inbox`，三个能力开关全开。
  - 收两类事件：频道里 @机器人（`app_mention`），以及私聊（`message.im`）。
  - 去掉开头的 `<@机器人>`，并反转义 Slack 的 `&amp;` 等。
  - 不处理：自己和别的机器人发的消息、编辑与删除、Slack 重发的同一事件。
  - 绑群时用 `conversations.info` 记下频道名，存成“#频道名”，网页上显示。
  - 私聊发码时用 `users.info` 取昵称，网页确认时给本人看是谁发来的。
  - 在话题里 @它，就回到话题里。
- **文案**：新增 `notify.slack.*` 一组，中英两份，用 mrkdwn。
- **其他**：实现了 `StatusReporter`。
- **错误归类**：
  - 429 和 `ratelimited` 按限流处理，等待时间取 `Retry-After`；
  - 令牌错、缺权限、应用被卸载，按整个通道不可用处理（通知保留）；
  - 机器人不在频道、频道不存在或已归档、消息太长，按不值得重试处理。

## 设计取舍（请过目）

1. **第一期不做斜杠命令**。调研报告里提过可选的 `/cohive`，但群通知正文里写的是“在编程工具里用 /cohive 12 处理”，指的是编程工具里的命令。在 Slack 里再注册一个同名斜杠命令，成员很容易打错地方。所以 @机器人 加私聊就够了，和钉钉一致；清单里也就不需要 `commands` 权限。
2. **按钮点击先回确认、再处理**，所以不需要钉钉那种“处理中”提示。结果出来后直接改原消息，其他群里的同一条审批消息照旧由 `After` 回写。
3. **审计里的绑群文字写成“Slack 群‘#频道名’”**。这沿用了已有的通用句式“绑定到{{通讯工具}}群”，对 Slack 来说“频道”更准确。要改的话得改通用句式，或给 Slack 单独一句，这次没动。

## 需要 lee 亲手做的实测步骤

凭据由 lee 亲手配置，实施会话和主脑都不经手。先合入本分支，再做下面几步，因为编排文件的变量映射要随 main 一起到测试服。

1. **建免费工作区**：打开 <https://slack.com/get-started>，用自己的邮箱建一个测试工作区。
2. **粘贴应用清单建应用**：打开 <https://api.slack.com/apps>，选 “Create New App → From a manifest”，选这个工作区，把仓库里 `deploy/slack-app-manifest.yaml` 的内容整段粘贴到 YAML 页，然后 Next、Create。
3. **拿两个令牌**：
   - “Install App → Install to Workspace”，复制 `xoxb-` 开头的机器人令牌；
   - “Basic Information → App-Level Tokens → Generate Token and Scopes”，加 `connections:write`，复制 `xapp-` 开头的应用级令牌。
4. **写进测试服**：在 pm-dev1 的 `~/cohive/deploy/.env` 里加两行：
   ```
   COHIVE_SLACK_BOT_TOKEN=xoxb-…
   COHIVE_SLACK_APP_TOKEN=xapp-…
   ```
   然后执行 `~/cohive-ops/upgrade.sh`。它会拉 main、重建容器、自动执行迁移 0014。看日志里有没有 “Slack: Socket Mode connected”，网页“服务器管理 → 设置 → 通讯工具”里 Slack 应显示“在线”。
5. **建频道、绑群、连账号**：
   - 在 Slack 里建一个测试频道，发 `/invite @Cohive`；
   - 网页“管理 → 工作空间 → 生成频道绑定码”，在频道里发 `@Cohive 绑定群 码`；
   - 网页“个人中心 → 连接 Slack”，在 Slack 里打开 Cohive 应用的“消息”标签，把码发过去，回网页确认。
6. **按 `docs/guides/slack.md` 第 7 节的验收清单走一遍**，重点看三件事：被 @ 的人有没有收到真正的提醒；审批按钮点了是否改成结果；不是管理员的人点按钮是否只有他自己看到提示。

实测时请顺手确认这几件只有真环境才知道的事：

- Socket 模式下，Slack 要求的确认时限是不是 3 秒。我们是收到就确认，正常不会超。
- 只放在消息块里的 @ 会不会提醒到人。我们同时在 `text` 里放了全文，作为保险。
- 免费版下，改 90 天前的消息会不会失败。审批消息的有效期比这短得多，影响不大。
