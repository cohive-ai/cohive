## 1. 动作 × 收件人对照表

规则通用：操作者本人永远不 @（群里只写名字）、不写会话提醒（N-3）；一个人只出现一次，优先级 原收件人 > 被 @ > 关注者。
关注者与被 @ 的人挂在本次动作的**主通知**（同一条群消息，首行末尾追加），不另发消息；只有没有任何原收件人时才单独一条（首行“#N 事件，由 某某 操作；关注（仅告知）…”）。

| 动作 | 原收件人（首行 @，谁该动手或直接告知；会话提醒 kind=事件名） | 关注者（首行追加“关注（仅告知）@…”；提醒 kind=watching） | 留言 @（首行追加“留言提到 @…”；提醒 kind=mentioned） |
|---|---|---|---|
| 发出（含发出时抄送） | 负责人：新单交给你 | 全部关注者（含刚抄送的） | — |
| 接单 | 发起人 | 是 | — |
| 退回 | 发起人 | 是 | — |
| 转交 | 新负责人（新单交给你）；另一条告知发起人（已转交） | 是，挂在“新单交给”那条 | — |
| 开始修复 | 发起人 | 是 | — |
| 请验证 | 发起人 | 是 | — |
| 关单（验证通过） | 负责人 | 是 | — |
| 重开 | 负责人；满 3 次另有一条“需要人介入”给双方 | 是，挂在“已重开”那条 | — |
| 作废 | 发起人作废：负责人；管理员作废：双方 | 是 | — |
| 留言 | 发起人、负责人（去掉操作者） | 是 | 被 @ 的人，只就这一条，不加关注 |
| 草稿上留言 | 不通知 | 不通知 | 不解析 |
| 改派（移出成员时） | 新接手人在要动手的状态下“新单交给你/请验证”；其余相关人一条“已改派” | 是，挂在第一条 | — |
| 催办第 1 档 | 当事人 | 不带 | — |
| 催办第 2 档 | 当事人 + 工作空间管理员 | 是（提醒 about=overdue_admin，客户端显示“你关注的单：催办”） | — |

关注者里自动去掉：操作者本人、已移出的成员、停用账号的成员（读的时候过滤，行保留）。

首行样例（中文）：`#12 新单交给 @bob，请接单、退回或转交；关注（仅告知）@carol @dave`；留言：`#12 有新留言，来自 alice，告知 @bob；留言提到 @eve；关注（仅告知）@carol`。
英文：`…; mentioned: @eve; watching (FYI): @carol`。钉钉、Slack 都走同一套渲染，@ 名单（atUserIds、<@id>）自动包含关注者和被 @ 的人。
会话提醒客户端：`#7 你关注的单：已接单（lee-codex）`、`#7 lee-codex 在留言里提到了你`；旧客户端遇到新类型显示“#7 有新动态”，兼容。

## 2. 我替你定的几处（需要你确认或改口）

1. **移除别人的关注**：只有发起人，以及网页上账号密码登录的工作空间管理员能移除；负责人能抄送别人，但不能移除别人（关注是旁人的知情权，不该由被监督的一方撤掉）。免密网页会话、编程工具都不算管理员。
2. **加别人（抄送）**：发起人、负责人；其他成员只能关注、取消自己。
3. **非相关成员能否留言**：不能。发起人、负责人、关注者能留言；其他人先关注再留言（不关注的话留言后收不到回复）。报错文案已写明“先关注这张单再留言”。
4. **已关闭、已作废、已退回的单**：仍可关注、取消（之后还会有留言）。归档工作空间里一律不能关注、取消、抄送。
5. 关注、取消关注不改版本号、不进动态时间线（与留言一样不打断别人基于版本的操作）；发单抄送记在起草或发出事件的 payload.cc 里。
6. 新工具 `cohive_watch_issue` 不需用户确认（只影响通知）；已加进 cohive init 的自动放行清单与三份示例配置。

## 3. 迁移（0016_issue_watchers.sql）与测试服

新建表 `issue_watchers`（主键 issue_id+member_id，外键指向 issues、members），`notifications` 加两列 `watchers`、`mentions`（jsonb，常量默认 `'[]'`），`member_alerts` 加 `about`（text，常量默认 `''`）。
测试服是 postgres:17：PostgreSQL 11 起加带常量默认值的列只改目录不重写表，建新表不碰旧数据，**可以直接在测试服库上执行**，旧通知、旧提醒取默认值，行为不变。删除草稿、彻底删除工作空间已先删关注者行，不会因外键失败。
