## 做了什么

1. **标志与网站图标**
   - 新增 `web/src/brand.tsx`，提供标志和几何字标两个组件，图形和 `docs/brand` 的 SVG 相同。外框和人的格子随文字颜色变化，智能体格子固定用品牌金。
   - 页头的旧六边形加“Cohive”文字，换成标志加字标；登录、注册卡片换成新标志。
   - `web/index.html` 的网站图标换成 `docs/brand/favicon.svg`，仍然内联，不加载外部文件。
2. **配色变量**：`web/src/styles.css`，改前改后的值见下表。
   - 新增 `accent` 系列，承担原来青绿的“可操作、被选中”职责：链接、主按钮、导航和标签页的当前项、焦点框、看板卡片悬停边框、邀请类型的选中卡片、单选框和复选框。
   - 青绿只保留状态含义：进行中、已接单、修复中、成功提示、在线、已绑定。
3. **等待色**：`amber` 改名为 `wait`，颜色从琥珀改成靛紫，和品牌金的色相相差约 155 度（测试要求至少 90 度）。用到的地方：待验证、已重开、看板“轮到你”的左边条和提示字、交接高亮动画、醒目提示框、未绑定群、离线、管理员角色标签、停用警告。含义一处没变。
4. **品牌页色名**：`site/brand.html` 色板的英文名从 Nero / Giallo 改成 Black / Gold（Bone、Carbon 原本就是英文普通词），和 `docs/brand` 一致；中文名夜黑、金黄、骨白、碳灰不变。
5. **测试**
   - `web/brand_test.go`，用 `go test ./...` 跑。两项检查：
     - `docs/brand` 与 `site/assets/brand` 文件集合相同、逐字节一致；
     - `web/index.html` 内联的网站图标就是 `docs/brand/favicon.svg`。
     - 故意改动一份副本后测试会失败，已验证。
   - `web/src/contrast.test.ts`，用 `make web` / `make build` 跑，直接读 `styles.css`，有四项检查：
     - 两种主题下 32 组“文字 / 背景”对比度不低于 4.5:1；
     - 跟随系统的深色块和 `data-theme="dark"` 块完全一致；
     - 深色主题覆盖了浅色的全部变量（品牌金除外）；
     - 等待色和品牌金的色相相差至少 90 度。
   - 为让测试读到样式表原文，`web/vite.config.ts` 给测试加了 `css.include`，只影响测试。
6. **文档**：`docs/brand/README*.md` 写明副本由 `web/brand_test.go` 把关；`docs/guides/m1-walkthrough.md` 的“琥珀色左边条”改成“靛紫色”。

**浅色主按钮的取舍（请过目）**：派活说“浅色主题下用加深的金色，保证文字对比度”。我把它拆成两层：

- **文字级的金色**（链接、当前项、选中边框）用加深金 #7a5800，在浅色底上 5.2 到 6.3:1。
- **主按钮底色**用略加深的 #e6ac00，配深色字 #1a1400，对比度 8.97:1。

如果主按钮也用 #7a5800 加白字，对比度是 6.51:1，同样达标，但按钮会发褐，不像品牌金。想改的话，只需把浅色的 `--accent-fill` 改成 #7a5800、`--accent-ink` 改成 #ffffff，测试会自动核对对比度。另外，金色按钮和浅色页面底之间的边界对比只有 1.81:1。按钮靠文字标签识别，不属于必须达到 3:1 的情况，但需要知道这一点。
