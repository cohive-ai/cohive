## 做了什么

1. **Go 多语言包 `internal/i18n`**
   - 基于 go-i18n v2.6.1，语言包在 `internal/i18n/locales/<语言>/*.json`。
   - 文件按区域分：common、cli、install、server、api、mcp、issue、secretscan；en 与 zh-CN 各 472 条。
   - 提供：`Lang.T`、`i18n.T`、`Errorf`、`Wrap`（可本地化的错误，`errors.Is` 照常可用）、`Message`（凡实现 `Localize(Lang)` 的错误都按语言渲染）、`Middleware`（按 Accept-Language 定语言并回写 Content-Language）、`Local()`（COHIVE_LANG > LC_ALL/LC_MESSAGES/LANG > macOS、Windows 界面语言 > 英文）。
2. **网页**
   - 接入 i18next 26.4.2、react-i18next 17.0.15。这两个刻意没用最新版：最新版是前一天才发布的，选了已发布两周以上的版本。
   - 语言包在 `web/src/locales/<语言>/<命名空间>.json`，按 common、issues、auth、me、server 分；en 477 条、zh-CN 472 条，差额是英文多出的单数形式。
   - 以英文语言包为类型来源，拼错键 `pnpm typecheck` 就报错。
   - 语言选择：本机设置 > 浏览器语言 > 英文。个人中心、登录页、注册页放了语言切换。请求都带 `Accept-Language`。
   - 带用户数据的 `Trans` 统一走 `safeTrans`（见下文“审核时改的”第 1 条）。
3. **各区域文案**（抽取与翻译由 6 个 sonnet 子代理分区完成，我逐区审核）
   - **网页**：除 Admin 页外全部完成。
   - **成员命令行、会话钩子**：钩子提醒英文以 `Cohive reminder:` 开头，中文仍是 `Cohive 提醒：`。
   - **技能文件**：改为 `internal/skill/<语言>/SKILL.md` 中英两版。`cohive init` 沿用项目里已有技能文件的语言，没有时用命令行语言。
   - **安装脚本**：服务器按 `?lang=` > Accept-Language > 缺省语言渲染；网页复制的命令总带 `?lang=`，地址加了单引号（zsh 会把 `?` 当通配符）。
   - **运维命令行 `cohive-server`**。
   - **单机运维脚本**：`scripts/lib/cohive-i18n.sh` 内置中英两套，不进社区翻译。
   - **接口**：报错按请求语言，响应加稳定的 `code` 字段，取值写在 `httpapi.go` 的注释里。
   - **MCP**：每种语言各建一个服务，工具说明、参数说明、输出结构说明都按语言；第一段用服务器缺省语言。
   - **底层包**：issue 状态名与状态机说明、secretscan 规则名都可按语言输出；保留了固定中文的旧函数给 core、notify 用。
4. **缺省语言**
   - `cohive-server serve` 读 `COHIVE_DEFAULT_LANGUAGE`：不设为英文，非法值启动即报错并列出可用语言。
   - Docker 的 compose、`.env.example` 与单机的 `server.env.example` 都加了这一项，带中英注释。
5. **服务器日志一律英文（D7）**：serve 的启动信息、`log.Printf`、数据库与迁移等底层报错都已改为英文。
6. **社区规范与文档**
   - **社区规范**：
     - CONTRIBUTING 英文版与中文版 `CONTRIBUTING.zh-CN.md`；
     - CODE_OF_CONDUCT（Contributor Covenant 2.1 官方原文，举报邮箱处是占位）；
     - SECURITY（中英）；
     - `.github` 下：议题模板（问题、建议、翻译）与 config、合并请求模板、`release.yml`（发布说明按标签分类）、`dependabot.yml`、`workflows/ci.yml`；
     - `docs/i18n/LANGUAGES.md`（语言与维护者登记）；
     - `docs/maintainers.zh-CN.md`（给 lee 的维护者手册）。
   - **README**：中英两版都加了“参与贡献”一节和 contrib.rocks 贡献者头像墙。英文版的语言说明如实写成“英文支持进行中，Admin 页、群通知和部分服务器消息仍是中文”。

## 合入后会变的地方（请主脑留意）

1. **测试服必须加 `COHIVE_DEFAULT_LANGUAGE=zh-CN`**，否则未指定语言的接口报错、MCP 工具说明和安装脚本都会变英文；群通知在第二段之前仍是中文。
2. **服务器日志和启动信息变成英文**，例如 `Group notifications: Telegram enabled`。
3. **成员命令行按系统语言显示**（第一段的过渡做法），报错也按这个语言请求。终端是 `LANG=en_US.UTF-8` 的成员会看到英文；临时可设 `COHIVE_LANG=zh-CN`，第二段改为跟随账号语言。
4. **网页时间格式**：绝对时间改为 Intl 格式，中文显示“2026年10月17日 13:03”，原来是“2026-10-17 13:03”；相对时间中文显示“5分钟前”，原来是“5 分钟前”。
5. **重新执行 `cohive init` 的影响**：Codex 配置块的标记行改为固定英文（`# >>> cohive (generated by cohive init; ...)`），老仓库重新执行时会有一次性的注释行改动。技能文件内容也有小改（钩子提醒两种语言都认）。
6. **网页“绑定新电脑”的安装命令**：变成 `curl -fsSL 'https://…/install.sh?lang=zh-CN' | sh -s -- --login`。
7. **接口错误响应**：都多了 `code` 字段。另外 `issue.TransitionError` 原先在网页接口里会落到 500，现在是 409 `conflict`。
