# 第一阶段·里程碑二：只读看板 实现计划

**目标：** 浏览器打开协作服务地址即可看到“每张问题单现在等谁处理”，以及每张单的详情与动态时间线；只读，自动刷新。

**架构：** 服务端新增只读 JSON 接口 `/api/v1/*`（复用 MCP 的令牌鉴权与业务层），并托管打包好的看板静态文件（Go `embed`）。看板是 React + Vite 单页应用，代码式路由。

**依据：** [docs/plan.md](../../plan.md) 第 5、8.1 节

## 全局约束

- 看板不加载任何外部资源（字体、脚本、统计），断网内网可用。
- 只读：看板不提供任何改变问题单的操作。
- 登录用成员令牌，看到的范围与该成员在编程工具里一致（他人草稿不可见）。
- `go test ./...` 不依赖 Node：`web/dist` 未构建时，服务端返回提示页。
- 前端依赖锁定精确版本。

## 接口

| 路径 | 说明 |
|---|---|
| `GET /api/v1/me` | 当前成员与工具 |
| `GET /api/v1/board` | 成员列表 + 问题单（含 `holder` 当前处理人、`needs` 待办说明）；已结束的只含 7 天内 |
| `GET /api/v1/issues?q=&service=&status=` | 搜索与过滤 |
| `GET /api/v1/issues/{id}` | 详情与动态 |

“当前处理人”规则：草稿、待验证、已退回 → 发起人；待接单、已接单、修复中、已重开 → 负责人；已关闭 → 无。

## 任务

1. **视图结构共享**：把 `IssueView`、`EventView` 与转换函数从 `mcpserver` 移到 `internal/view`，MCP 测试保持通过。
2. **看板数据**：`store.ListBoard`、`core.Holder`、`core.Board`；测试：处理人规则、他人草稿不可见、超过 7 天的已结束单不出现。
3. **只读接口**：`internal/httpapi`；测试：未带令牌 401、看板按处理人返回、详情、他人草稿 404、未知接口返回 JSON 404。
4. **静态托管**：`web/embed.go` 嵌入 `web/dist`；单页应用回退到 `index.html`，`/api`、`/mcp`、`/healthz` 不回退；未构建时返回提示页。测试覆盖回退规则。
5. **看板前端**：登录页、看板页（按人分列，每 5 秒刷新，单子换人时高亮）、全部问题单列表、详情页（字段、复现脚本、动态时间线）。浏览器实测截图自查，含窄屏。
6. **构建与文档**：`make web`、`make build` 先构建前端；更新操作指南。
