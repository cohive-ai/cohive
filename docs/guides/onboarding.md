# 新成员接入

成员、设备、邀请、审批都在网页上管理。新成员打开邀请链接注册，在电脑终端执行 `cohive login`、在浏览器里点“授权”即可完成配对；全程不需要复制任何密钥。通讯工具（Telegram）只是连接上去的，用于群里 @ 人和审批按钮，不是注册和登录的前提。

## 部署后：第一个管理员

服务首次启动时，如果还没有任何管理员，会在默认工作空间建一个管理员 `admin`，随机密码写在数据目录下的文件里（缺省为运行目录下的 `data/initial_admin_password`，可用环境变量 `COHIVE_DATA_DIR` 指定数据目录），只有服务器上能读。启动日志里只提示文件位置，不打印密码。

1. 在服务器上查看这个文件，用里面的成员名和密码登录网页。
2. 第一次登录必须修改密码，改完这个文件自动删除。
3. 忘记密码时，在服务器上执行（不会清空任何数据）：

   ```bash
   ./bin/cohive-server admin reset-password --name admin
   ```

   新密码只在终端显示一次，登录后须立即修改。

## 管理员：发邀请

管理操作（管理页的全部功能）只能在网页上用账号密码登录后进行；用 `cohive web` 免密打开的网页、编程工具的令牌都不能做管理操作，电脑被人拿到时不至于连带丢掉管理权限。群里的审批按钮不受影响（按点击者已连接的 Telegram 账号核对管理员）。

网页“管理 → 邀请”里生成邀请，把链接发给对方（群里、邮件、当面都行）：

| 邀请 | 次数 | 注册后 |
|---|---|---|
| 个人邀请 | 一次 | 立即生效；可设为管理员 |
| 团队邀请 | 可设次数（缺省 20） | 需要管理员在“管理 → 待审”里批准 |

- 链接只在生成时显示一次；默认 7 天有效（1 小时到 30 天可选），随时可以作废。
- 配好工作空间的 Telegram 群后，待审的注册和设备申请也会发到群里，管理员直接点“批准 / 拒绝”。

## 成员：三步

**1. 打开邀请链接注册**：填成员名（小写字母、数字、下划线、横线）、显示名、密码（至少 10 位）。团队邀请要等管理员批准后才能登录。

**2. 配对自己的电脑**：先安装 cohive 命令行（编程工具要能在 PATH 里找到它）：

```bash
make install-cli
```

然后在终端执行（网页“个人中心”里有带服务器地址的完整命令，一键复制）：

```bash
cohive login --server https://cohive.example.com
```

终端会自动打开浏览器授权页（同时显示链接和二维码）。没登录网页的话先登录，核对设备名和工具后点“授权”，终端随即显示“已登录”。

- **第一台电脑授权后立即生效；之后再加电脑需要管理员批准。** 等待期间终端会一直等，也可以随时按 Ctrl+C 或合上电脑：进度保存在本机，批准后执行 `cohive login --resume` 领取（24 小时内有效）。网络中断导致退出时同样可以这样继续。
- 仓库里已有 `cohive init` 生成的配置时，服务地址和要登录的工具从配置读取（在子目录里执行也行），一次授权同时登录 Claude Code 和 Codex。第一次登录某个地址时，终端会先显示地址请你按回车确认。
- 已配对的电脑再登录其他工具（`cohive login --tools codex`）直接签发，不必再授权。
- 令牌保存在 `~/.config/cohive/credentials.json`，只有你本人可读；`cohive status` 查看已登录的服务（不显示令牌）。

**3. 在项目目录执行 `cohive init`**（团队里有人做过并提交了配置就不用再做），之后在 Claude Code 里用 `/cohive`、在 Codex 里用 `$cohive`。

## 个人中心

- **免密打开网页**：在已配对的电脑上执行 `cohive web`，浏览器直接登录，不用输密码。这种登录能用个人中心和看板，但不能做管理操作，管理员要做管理请用账号密码登录。
- **我的设备**：查看、吊销自己的电脑；吊销后那台电脑上的令牌立即失效。
- **连接 Telegram**：点“连接 Telegram”，在 Telegram 里打开机器人即完成连接。连接后群通知能 @ 到你；管理员连接后可以在群里点审批按钮。同一工作空间里一个 Telegram 账号只能连一个成员。
- **改密码**：改完后你在其他浏览器上的登录会失效。

## 安全要点

- 授权页上的设备名由终端自报，只允许主机名字符。**只授权你自己刚刚在终端发起的那一次。**
- 终端只打开协作服务自己的授权页；服务端返回别的地址时直接报错。
- 设备授权 15 分钟内有效，令牌只交付一次，只有发起授权的那台电脑能领取。
- 网页登录用仅限本站的 Cookie，跨站请求一律拒绝；改密码、重置密码会让其他登录失效。

## cohive init 写入的文件

| 工具 | 文件 |
|---|---|
| Claude Code | `.mcp.json`（`cohive` 条目）、`.claude/settings.json`（确认规则）、`.claude/skills/cohive/SKILL.md` |
| Codex | `.codex/config.toml`（`# >>> cohive` 与 `# <<< cohive` 之间的一段）、`.agents/skills/cohive/SKILL.md` |

- 只改动自己管理的部分，原有配置保留；重复执行结果相同。
- 这些文件**不含令牌**：编程工具通过本机命令 `cohive mcp-proxy` 连接协作服务，令牌由它从本机凭据文件读取。可以放心提交进仓库，团队共用。
- 第一次在编程工具里打开项目时，会询问是否信任项目、是否启用 `cohive` 这个 MCP 服务，都选同意。
- `.claude/settings.json` 里的 `enabledMcpjsonServers` 会随仓库共享，审查合并请求时留意 `.mcp.json` 与它的改动。
- `.mcp.json` 和 `.codex/config.toml` 里有协作服务地址，公开仓库要注意。

## 备用方式

自动化脚本、没有浏览器的环境：管理员用 `cohive-server token issue --member 成员名 --tool 工具` 签发令牌，通过可靠渠道交给对方，从标准输入传入（不会进 shell 历史）：

```bash
pbpaste | cohive login --server https://cohive.example.com --token-stdin
```

## 常见问题

- **终端提示授权被拒绝**：你在浏览器里点了拒绝，或管理员没有批准。重新执行 `cohive login`。
- **编程工具里提示“Cohive 令牌无效或已吊销”**：设备或令牌被吊销了，执行 `cohive login --force` 重新配对。重新配对算新增一台设备，需要管理员批准；成功后会自动吊销这台电脑之前的设备，旧设备上只登录了、这次没重新登录的工具，按提示用 `cohive login --tools` 补登即可。
- **电脑丢失**：在网页“个人中心 → 我的设备”吊销它（或请管理员在“管理 → 设备”里吊销）。
- **连接 Telegram 时提示没有启用机器人**：服务没有设置 `COHIVE_TELEGRAM_BOT_TOKEN`。
