# 新成员接入

一个项目一个群，对应 Cohive 的一个工作空间。账号是全局的：同一个人只有一个登录名、一个密码、一个 Telegram 连接，可以在多个工作空间里；角色（管理员 / 成员）按工作空间分别设置。电脑配对一次，就能用于你所在的全部工作空间。

成员、设备、邀请、审批都在网页上管理。新成员打开邀请链接注册，在电脑终端执行 `cohive login`、在浏览器里点“授权”即可完成配对；全程不需要复制任何密钥。通讯工具（Telegram）只是连接上去的，用于群里 @ 人和审批按钮，不是注册和登录的前提。

## 角色

| 角色 | 能做什么 |
|---|---|
| 服务器管理员 | 建、删工作空间，指定各工作空间的管理员；停用、启用账号；授予服务器管理员；管理任一工作空间（但不是成员时看不到它的问题单，可在管理页把自己加进去） |
| 工作空间管理员 | 本工作空间的加人、发邀请、审批、移出（含转交）、改角色、群设置与显示名；批准本工作空间成员的新设备 |
| 成员 | 看板、经编程工具收发问题单；问题单的发出、接单、关闭仍按发起人与负责人，与角色无关 |

## 部署后：第一个管理员

服务首次启动时，如果还没有任何服务器管理员，会建一个账号 `admin`：它是服务器管理员，也是 `default` 工作空间的管理员。随机密码写在数据目录下的文件里（缺省为运行目录下的 `data/initial_admin_password`，可用环境变量 `COHIVE_DATA_DIR` 指定数据目录），只有服务器上能读。启动日志里只提示文件位置，不打印密码。

用 Docker 部署时文件在数据卷里，执行 `docker compose exec cohive cat /data/initial_admin_password` 查看；下文的服务器命令也都在容器里执行，例如 `docker compose exec cohive cohive-server admin reset-password --name admin`（见 [用 Docker 部署](deploy-docker.md)）。

1. 在服务器上查看这个文件，用里面的登录名和密码登录网页。
2. 第一次登录必须修改密码，改完这个文件自动删除。
3. 忘记密码时，在服务器上执行（不会清空任何数据）：

   ```bash
   ./bin/cohive-server admin reset-password --name admin
   ```

   新密码只在终端显示一次，登录后须立即修改。

4. **设置对外地址**：在“服务器管理 → 设置”里确认同事访问用的地址（例如 `https://cohive.example.com`），然后保存。第一次打开时会预填你当前访问用的地址，但不会自动保存，请先确认它不是 `localhost` 或只有你能打开的地址。群消息里的链接、编程工具经隧道访问时的主机名都用它。也可以用环境变量 `COHIVE_EXTERNAL_URL` 指定并锁定。

## 服务器管理员：建工作空间

网页顶栏“服务器管理 → 工作空间”里填名字（小写字母、数字、下划线、横线；建后不能改，因为项目配置按名字引用），可选填首位管理员的登录名（默认是你自己）。建好后到该工作空间的“管理 → 工作空间”填群编号：把机器人拉进项目群，在群里发 `/chatid` 获取。**一个群只能绑一个工作空间。**

没有任何问题单（含草稿）的工作空间可以删除，用于建错名字的情形。

## 工作空间管理员：加人

管理操作只能在网页上用账号密码登录后进行；用 `cohive web` 免密打开的网页、编程工具的令牌都不能做管理操作，电脑被人拿到时不至于连带丢掉管理权限。群里的审批按钮不受影响（按点击者已连接的 Telegram 账号核对，并且只对本群对应的工作空间有效）。

**已有账号的人**（在别的工作空间用过 Cohive）：“管理 → 成员 → 添加已有账号”，输入他的登录名（只能精确输入，不能浏览全部账号），核对显示名后选角色加入，立即生效。被移出过的人再加回来，以前的问题单会重新接上。

**新人**：“管理 → 邀请”里生成邀请，把链接发给对方：

| 邀请 | 次数 | 新人注册后 | 已有账号的人打开后 |
|---|---|---|---|
| 个人邀请 | 一次 | 立即生效；可设为管理员 | 点“以 X 身份加入”立即生效 |
| 团队邀请 | 可设次数（缺省 20） | 需要管理员在“管理 → 待审”里批准 | 生成“加入申请”，同样需要批准 |

- 链接只在生成时显示一次；默认 7 天有效（1 小时到 30 天可选），随时可以作废。
- 登录名全服务器唯一：新人注册时不能和已有账号、别的工作空间里等待批准的申请重名。
- 配好群后，待审的注册与加入申请会发到本工作空间的群里，设备申请会发到申请人所在的每个群里，管理员直接点“批准 / 拒绝”；在任一处处理后，各群里的消息都会改成结果。

## 成员：三步

**1. 打开邀请链接**：新人填登录名、显示名、密码（至少 10 位）注册；团队邀请要等管理员批准后才能登录。已经有账号的人先登录，再点“以 X 身份加入”。

**2. 安装命令行并配对自己的电脑**（每台电脑只做一次）：不需要装 Go，也不需要能读代码仓库：命令行由团队自己的协作服务提供，版本与服务端一致（详见 [install-cli.md](install-cli.md)）。网页“个人中心 → 绑定新电脑”里有带服务器地址的命令，一键复制，装完会接着配对：

```bash
curl -fsSL https://cohive.example.com/install.sh | sh -s -- --login
```

Windows 在 PowerShell 里执行 `$env:COHIVE_LOGIN=1; irm https://cohive.example.com/install.ps1 | iex`。默认装在 `~/.local/bin`；提示不在 PATH 里时按提示加上，并从终端重新启动编程工具（它要能在 PATH 里找到 `cohive`）。开发者在仓库里也可以 `make install-cli`。已经装好命令行的电脑只需执行 `cohive login --server https://cohive.example.com`。

配对时终端会自动打开浏览器授权页（同时显示链接和二维码）。用账号密码登录网页，核对设备名、工具和“批准后可用于”的工作空间后点“授权”，终端随即显示“已登录”，并列出每个工作空间拿到的工具。

- **第一台电脑授权后立即生效；之后再加电脑需要你所在任一工作空间的管理员批准**（批准后这台电脑可用于你全部的工作空间）。等待期间终端会一直等，也可以随时按 Ctrl+C 或合上电脑：进度保存在本机，批准后执行 `cohive login --resume` 领取（24 小时内有效）。
- 仓库里已有 `cohive init` 生成的配置时，服务地址和要登录的工具从配置读取（在子目录里执行也行）。第一次登录某个地址时，终端会先显示地址请你按回车确认。
- 设备密钥与令牌保存在 `~/.config/cohive/credentials.json`，只有你本人可读；`cohive status` 查看（不显示密钥与令牌）。

**3. 在项目目录执行 `cohive init`**（团队里有人做过并提交了配置就不用再做），之后在 Claude Code 里用 `/cohive`、在 Codex 里用 `$cohive`。你在多个工作空间时要指定这个项目属于哪一个：

```bash
cohive init --workspace pay
```

**4. 第一次打开项目时信任钩子**（会话内提醒要用）：

- **Claude Code**：在这个文件夹第一次打开时选“信任此文件夹”（与启用 MCP 服务是同一步）。
- **Codex**：在项目目录执行一次命令行版 `codex`，同意信任项目；启动时提示“Hooks need review”，选“Trust all and continue”，信任 cohive 的两条钩子（`SessionStart`、`UserPromptSubmit`）。**只用桌面版的人也要先这样做一次**：桌面版里没有信任钩子的入口，命令行版信任之后桌面版随之生效。**每台电脑、每个克隆目录各要信任一次**；换了服务地址或工作空间（重新执行 `cohive init` 改了这两项）要重新信任，只是重复执行 `cohive init` 不用。

## 会话内提醒

两家的命令行版与桌面版都支持（2026-10-17 实测）：Claude Code 需信任文件夹；Codex 需在项目目录执行一次命令行版 `codex` 选全部信任。

有与你有关的新动态时（单子交给你、被退回、请你验证、被重开、需要人介入、你发的单被接单、你修的单被关闭），**在你发出下一句话时，由智能体在这一轮最终答复的末尾（正文之后另起一行）告诉你**，例如“Cohive 提醒：#12 tester-a 交给你处理，可用 /cohive 12 查看”；新开会话时，第一次回复的末尾会告诉你还有几张待处理的单。放在末尾是因为回复常常很长，放开头容易被略过。提醒只有单号、动作、谁，不含标题与正文，要看内容用 `/cohive 12`（Codex 为 `$cohive 12`）。同一条在一个会话里只说一次。

- **编程工具空闲、或者会话还没开始时不会提醒**：它只在你发消息时才有机会插话。这时靠 Telegram 群里的 @。
- Claude Code 还会在界面上单独显示一行“Cohive 提醒”；Codex 桌面版不显示这一行，只靠智能体在回复里说。
- 协作服务连不上、慢、令牌失效时不提醒，也不会拖慢或拦住你的消息（最多等 2 秒；同一会话 20 秒内只查一次）。
- 自己做的操作不提醒自己；同一会话里同一条只提醒一次，开着的几个会话各提醒一次。
- 没有提醒时，执行 `cohive init` 结尾打印的那条 `cohive hook --check …` 命令排查。
- 不想要：`cohive init --no-hooks`（只移除 cohive 的钩子，你自己的钩子不动）。
- 团队里有人的 `cohive` 还是旧版本时，钩子会报“未知命令”，不影响使用；升级 `cohive` 即可。
- Codex 在 git 工作树里读的是主检出目录的钩子配置：`cohive init` 生成的文件要提交。

## 加入新的工作空间之后

不用重新配对。克隆新项目（配置已在仓库里）后直接打开编程工具：本机转发器发现还没有这个工作空间的令牌，会用这台电脑的设备密钥自动签发。也可以在仓库里执行 `cohive init --workspace 名字`，或再执行一次 `cohive login` 补齐全部工作空间的令牌。

## 个人中心

- **我的工作空间**：你所在的工作空间与角色，点进去即可切换；网页顶栏也有切换下拉框。
- **免密打开网页**：在已配对的电脑上执行 `cohive web`，浏览器直接登录，不用输密码。这种登录能用个人中心和看板，但不能做管理操作，也不能接受邀请、授权新设备，这些请用账号密码登录。
- **我的设备**：查看、吊销自己的电脑（按工作空间列出它上面的令牌）；吊销后那台电脑上的令牌与设备密钥立即失效。
- **连接 Telegram**：点“连接 Telegram”，在 Telegram 里打开机器人即完成连接，全部工作空间通用。连接后群通知能 @ 到你；管理员连接后可以在群里点审批按钮。一个 Telegram 账号只能连接一个 Cohive 账号。
- **改密码**：改完后你在其他浏览器上的登录会失效。

## 移出与停用

- **移出**（工作空间管理员，作用于一个工作空间）：“管理 → 成员 → 移出”会列出他名下尚未结束的问题单（作为负责人的和作为发起人的）以及他负责的服务，每一项选一个接手人后才能移出。改派会写进问题单的时间线，并给接手人发群通知。移出后他在这个工作空间的令牌立即失效，别的工作空间不受影响。
- **停用**（服务器管理员，作用于整个人）：吊销他全部的设备与令牌、注销全部网页登录、断开 Telegram，不能再登录。停用不要求转交；管理页会标出“已停用”和他的待处理单数，可以单独“改派”。启用后设备不会恢复，需要重新 `cohive login` 并由管理员批准。

## 管理操作记录

所有管理操作都记在一张只追加的记录里（不能修改、删除），与操作本身同时生效：操作失败就不会留记录。

- **在哪看**：工作空间“管理 → 记录”只看本工作空间的；“服务器管理 → 记录”看全部（可按工作空间筛选，含已删除的）。都可按类型、操作人、入口筛选，按时间倒序，每页 50 条。服务器上也可以用 `cohive-server audit list`（参数同上，`--before` 翻页）。
- **记了什么**：审批（注册申请、加入申请、新设备，批准与拒绝，网页与群按钮都记）、改角色、邀请的生成与作废、设备吊销（含本人吊销自己的、`cohive login --force` 吊销本机旧设备）、直接加入、转交与移出（含转交给了谁）、停用与启用、服务器管理员的授予与撤销、工作空间的建删与设置修改、命令行重置密码、修改账号资料、签发与吊销令牌、登记服务负责人。另外，本人做的、改变“谁能凭什么进来”的操作也记：首台设备的本人授权、凭个人邀请注册或加入、连接与断开 Telegram、改密码、首次启动建初始管理员。登录、登出不记。
- **被拒的管理请求也记**：已认证的身份调管理接口（工作空间管理、服务器管理、授权设备、接受邀请、查看记录）被拒时记一条“被拒的管理请求”——编程工具令牌、设备密钥、`cohive web` 免密网页被挡（管理操作只认账号密码登录的网页），或用密码登录了但没有权限；群里没有审批权限的人点审批按钮也记。记的是接口模板（例如 `POST /api/v1/invites/{code}/accept`），不记路径里的邀请码等实际值。没登录的请求、访问自己不在的工作空间（返回“不存在”）不记；同一身份（账号加凭据种类）同一接口一分钟内只记一条。这类记录的入口可能是“编程工具令牌”。
- **每条有什么**：操作人（服务器命令行操作时为空，写“服务器命令行”）、入口（网页 / 群按钮 / 服务器命令行 / 成员本机命令行 / 服务器自动）、工作空间（服务器级操作为空）、对象、必要的附加信息（例如改角色前后的值、移出时每张单转给了谁）、时间。**绝不记密码、令牌、邀请码、设备密钥。**
- **工作空间管理员看不到的**：停用账号、在服务器管理页批准设备这类服务器级操作只在服务器管理页显示。
- **上线前的历史**：升级时把库里已记了审批人的注册、加入、设备审批补成记录，入口标“未知（功能上线前）”；设备审批库里没有决定时间，批准的取设备创建时间，拒绝的取申请时间并标“时间为近似值”。其余历史管理操作库里没有操作人与时间，无从补。
- **防篡改到哪一步**：程序没有修改、删除记录的路径，数据库里还有触发器拦截修改与删除；能直接改数据库结构的人仍可绕过，这一层防的是程序缺陷与误操作。

## 安全要点

- 授权页上的设备名由终端自报，只允许主机名字符。**只授权你自己刚刚在终端发起的那一次。**
- 终端只打开协作服务自己的授权页；服务端返回别的地址时直接报错。
- 设备授权 15 分钟内有效，设备密钥与令牌只交付一次，只有发起授权的那台电脑能领取。
- 设备密钥只能用来签发你所在工作空间的令牌、`cohive web` 免密登录、吊销你自己的设备，不能直接调用问题单与管理接口。
- 网页登录用仅限本站的 Cookie，跨站请求一律拒绝；改密码、重置密码会让其他登录失效。

## cohive init 写入的文件

| 工具 | 文件 |
|---|---|
| Claude Code | `.mcp.json`（`cohive` 条目）、`.claude/settings.json`（确认规则；`hooks` 里会话开始、提交提示词各一组 `cohive hook …`）、`.claude/skills/cohive/SKILL.md` |
| Codex | `.codex/config.toml`（`# >>> cohive` 与 `# <<< cohive` 之间的一段，含两条钩子）、`.agents/skills/cohive/SKILL.md` |

- 只改动自己管理的部分，原有配置保留；重复执行结果相同。
- 这些文件**不含令牌**：编程工具通过本机命令 `cohive mcp-proxy --server … --workspace … --tool …` 连接协作服务，令牌由它从本机凭据文件读取。可以放心提交进仓库，团队共用。
- 第一次在编程工具里打开项目时，会询问是否信任项目、是否启用 `cohive` 这个 MCP 服务，都选同意；Codex 还要在项目目录执行一次命令行版 `codex` 信任 cohive 的两条钩子（见上文第 4 步）。
- `.claude/settings.json` 里的 `enabledMcpjsonServers` 会随仓库共享，审查合并请求时留意 `.mcp.json` 与它的改动。
- `.mcp.json` 和 `.codex/config.toml` 里有协作服务地址与工作空间名，公开仓库要注意。

## 备用方式

自动化脚本、没有浏览器的环境：管理员用 `cohive-server token issue --workspace 名字 --member 登录名 --tool 工具` 签发令牌，通过可靠渠道交给对方，从标准输入传入（不会进 shell 历史）：

```bash
pbpaste | cohive login --server https://cohive.example.com --token-stdin
```

## 常见问题

- **终端提示授权被拒绝**：你在浏览器里点了拒绝，或管理员没有批准。重新执行 `cohive login`。
- **编程工具里提示“你还不是工作空间 X 的成员”**：请那个工作空间的管理员把你加进去，加入后重新打开编程工具即可。
- **编程工具里提示“Cohive 令牌无效或已吊销”**：如果你被移出了这个工作空间，请联系管理员；否则执行 `cohive login --force` 重新配对。重新配对算新增一台设备，需要管理员批准；成功后会自动吊销这台电脑之前的设备。
- **提示“这台电脑是旧版配对”**：M5 时配对的电脑没有设备密钥，旧令牌照常能用，但新工作空间的自动签发和 `cohive web` 需要先执行 `cohive login --force` 重新配对（需要管理员批准）。
- **电脑丢失**：在网页“个人中心 → 我的设备”吊销它（或请管理员在“管理 → 设备”里吊销）。
- **会话里没有 Cohive 提醒**：执行 `cohive hook --check --server … --workspace … --tool …`（`cohive init` 结尾有完整命令）；Codex 先确认在项目目录执行过命令行版 `codex` 并选了“Trust all and continue”。
