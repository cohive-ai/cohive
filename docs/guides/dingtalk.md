# 在自己的钉钉企业里接入 Cohive

> 第 1–6 步只在钉钉里操作，第 7 步起在 Cohive 里操作。钉钉后台的菜单名称可能和下面写的略有出入，以实际界面为准；遇到对不上的地方请记下来反馈（见文末“请实测并反馈”）。只支持钉钉国内版；国际版（dingtalk.io）的卡片能力还没核实。

接好之后能做到这些：

- 问题单轮到谁处理（新单、请验证、被重开等），项目群里会出现一张卡片并 @ 到他；单子被接、验证通过关闭时，也会出卡片告知另一方。卡片里只有单号、交接关系和指引，正文不进群。完整的事件清单见 [群通知](group-notify.md) 第 3 节。
- 有人申请注册、加入或添加新设备时，群里会出现审批卡片，管理员直接点“批准”或“拒绝”，卡片随即改成结果。
- 成员在 Cohive 网页“个人中心”连接自己的钉钉账号之后，才能被 @，也才能在群里点审批按钮。

Cohive 只需要**出站**访问钉钉。它主动连到钉钉（Stream 模式），不需要公网 IP、域名或内网穿透。

## 0. 开始前

- **钉钉组织**：你需要是组织的管理员，或者被管理员授予了“开发者权限”。个人可以在钉钉客户端里“创建团队”，自己就是管理员。
- **所有成员都在这个组织里**：机器人只能进本组织的**内部群**。钉钉里的“普通群”（不属于任何组织的群）和外部群都不行。
- **一个钉钉应用只接一台 Cohive**：同一个应用同时被两台 Cohive 连着时，钉钉会把按钮点击随机发给其中一台，另一台就收不到。测试和正式不要共用一个应用。
- **额度**：钉钉标准版（免费）的开放接口每月约 1 万次，Webhook 与 Stream 推送合计每月 3000 次（以钉钉公告为准）。3–15 人的团队一般用不完。如果用完了，群里的按钮会失效，审批照常在 Cohive 网页“管理 → 待审”里做。

## 1. 创建企业内部应用

1. 用管理员账号登录钉钉开发者后台 <https://open-dev.dingtalk.com>。
2. 进入“应用开发 → 企业内部应用”，点“创建应用”。名称填 `Cohive`，简介写“团队协作通知与审批”，上传一个图标。
3. 创建好后进入应用，在“凭证与基础信息”里找到 **Client ID**（原 AppKey）和 **Client Secret**（原 AppSecret）。

   Client Secret 相当于密码：不要发到群里，不要截图外传，第 7 步只填进 Cohive 服务器。

## 2. 添加机器人能力，开启 Stream 模式

1. 在应用里点“添加应用能力”，选“机器人”。
2. 填机器人名称（建议 `Cohive`，后面在群里 @ 的就是它）、简介、头像。
3. **消息接收模式选“Stream 模式”**。不要选 HTTP 模式，HTTP 模式要求你提供一个公网可访问的地址。
4. 保存。

## 3. 开通权限

在“权限管理”里搜索并申请下面两项：

| 权限 | 用途 |
|---|---|
| 企业内机器人发送消息权限 | 往群里发通知、回复命令 |
| 互动卡片实例写权限（`Card.Instance.Write`） | 发通知卡片和审批卡片，审批后改卡 |

Cohive 不读通讯录，不需要通讯录权限。成员连接钉钉时，机器人从私聊消息里拿到他的钉钉编号和昵称。

## 4. 在卡片平台建两个卡片模板

入口：开发者后台 → 卡片平台（也可能在“开放能力 → 互动卡片”下），点“新建模板”。模板**发布后不能再编辑**，先点“保存”并预览，确认没问题再发布。

### 4.1 通知卡片（名称：Cohive 通知）

| 组件 | 设置 |
|---|---|
| 标题 | 绑定变量 `title`（字符串） |
| 正文（Markdown 或富文本组件） | 绑定变量 `content`（字符串，内容是 Markdown） |

正文必须使用支持 Markdown 的组件，才能渲染卡片内的 @ 标签。Cohive 会同时发送群消息提醒名单 `atUserIds`、卡片内名单 `cardAtUserIds`，并在正文中生成 `<a atId=钉钉userId>钉钉昵称</a>`；仅写普通的 `@名字` 不会生成卡片内的 @ 高亮。

不需要按钮。预览用的示例数据：`title` 填“#12 新单交给 @张三”，`content` 填几行 Markdown。

### 4.2 审批卡片（名称：Cohive 审批）

| 组件 | 设置 |
|---|---|
| 正文（Markdown 或富文本组件） | 绑定变量 `content`（字符串） |
| 结果文字（文本组件） | 绑定变量 `status`（字符串），例如“已批准（审批人 lee）” |
| 提示文字（文本组件，小字） | 绑定**私有**变量 `tip`（字符串）：只给点按钮的那个人看，例如“你没有审批权限”“已批准” |
| 按钮“批准” | 点击事件选**回传请求**，回传参数 `{"decision": "approve"}` |
| 按钮“拒绝” | 点击事件选**回传请求**，回传参数 `{"decision": "reject"}` |

- 如果平台支持“按变量控制显示”，给两个按钮设置：变量 `pending` 为 `true` 时才显示（Cohive 传的是字符串 `"true"`/`"false"`，变量类型按平台要求选）。审批处理完后，Cohive 会把 `pending` 改成 `false`，按钮就消失了。不支持也没关系，按钮会一直留着，处理后再点会提示“已处理”。
- 按钮的名字是写在模板里的固定文字，Cohive 不会随语言改它，多语言团队怎么写见 4.3。
- 回调方式如果要选，选 **Stream**。
- 卡片平台如果不支持“私有变量”，`tip` 用普通变量也行，只是所有人都会看到最后一次点击的提示。

两个模板都发布后，记下各自的**模板编号**（cardTemplateId）。

### 4.3 群消息语言

群里卡片上的文字有两个来源，语言的决定方式不同：

- **Cohive 传入的变量**（语言随工作空间）：通知卡片的 `title`、`content`；审批卡片的 `content`、`status`（“已批准（审批人 …）”这类结果）、`tip`（点按钮后的提示）。没配卡片模板时发的纯 Markdown 消息、机器人在群里的回复也由 Cohive 生成。这些文字的语言取群所属工作空间的设置（工作空间管理员在网页“管理 → 工作空间”里设置）；工作空间没设置时，用服务器缺省语言 `COHIVE_DEFAULT_LANGUAGE`（`en` 或 `zh-CN`，不设时为英文，见 [群通知](group-notify.md)）。
- **你在钉钉卡片平台模板里写死的文字**：Cohive 不会翻译，也不会改。按本文 4.1、4.2 搭出来的模板里，这样的文字只有审批卡片上两个按钮的名字（“批准”“拒绝”）；通知卡片除了绑定变量的两个组件，没有别的文字。按钮回传的参数 `{"decision": "approve"}`、`{"decision": "reject"}` 与语言无关，改按钮名字不影响功能。

要注意的限制：Cohive 目前每台服务器只配**一个**通知模板编号和**一个**审批模板编号（`COHIVE_DINGTALK_NOTICE_TEMPLATE`、`COHIVE_DINGTALK_APPROVAL_TEMPLATE`），所有工作空间共用，没有“按语言选模板”的配置项，也不会把按钮名字作为变量传给模板。所以模板里写死的文字要自己迁就：

1. **所有工作空间都用同一种语言**：按那种语言写按钮名字即可（英文用 `Approve`、`Reject`）。如果你是从中文模板改过来的，把按钮名字改掉再发布；已发布的模板不能再编辑，需要另建一个新模板，换上新的模板编号（改 `COHIVE_DINGTALK_APPROVAL_TEMPLATE` 后重启服务）。
2. **既有中文工作空间、又有英文工作空间**：模板里写死的文字写成中英并列，例如按钮名字 `批准 / Approve`、`拒绝 / Reject`，不要加只有一种语言的固定标题或前缀。这样不论哪个工作空间的群看到的都能读懂。
3. **其他写死的文字**（比如你自己在卡片上加的“请审批”提示条、卡片标题前缀）：同样改成中英并列，或者干脆删掉，把需要显示的内容交给 Cohive 传入的变量。

确实需要两套互相独立的模板（按语言各一套）时，现在的办法只有给英文团队单独部署一台 Cohive 和一个钉钉应用（一个钉钉应用只接一台 Cohive，见第 0 节）。要不要支持按语言选模板，欢迎在项目里提议。

改完后可以用第 10 节的验收清单再走一遍：卡片上“已批准”“已拒绝”这类结果文字会随工作空间语言变化，英文工作空间里是 Cohive 生成的英文，按钮名字是你在模板里写的那一版。

**请帮个忙**：卡片平台如果有“导出 JSON”，把两个模板导出发给 lee。我们会附进仓库，以后别人接入时可以直接导入。

## 5. 发布应用

1. 进入“版本管理与发布”，创建一个版本。
2. 可见范围选参与试用的成员，或者全部员工。
3. 发布。机器人要在应用发布后才能加进群。

## 6. 建内部群并加机器人

1. 在钉钉里建一个**组织内部群**（例如“XX 项目协作”），把参与的同事拉进来。
2. 打开群设置 → 机器人 → 添加机器人，在企业机器人里找到 `Cohive` 并添加。

## 7. 把应用配置进 Cohive

Cohive 跑在哪台服务器上，由 lee 和你商量决定。两种情况：

- **用 lee 的测试服**：把 Client ID、Client Secret 和两个模板编号**私下**发给 lee（不要发到群里），由 lee 配置。
- **你自己部署 Cohive（推荐 Docker）**：按 [Docker 部署](deploy-docker.md) 把 Cohive 跑起来，然后在 `deploy/.env` 里填这几项：

  ```
  COHIVE_DINGTALK_CLIENT_ID=dingxxxxxxxx
  COHIVE_DINGTALK_CLIENT_SECRET=（Client Secret）
  COHIVE_DINGTALK_NOTICE_TEMPLATE=（通知模板编号）
  COHIVE_DINGTALK_APPROVAL_TEMPLATE=（审批模板编号）
  ```

  然后执行 `docker compose up -d`。改了 `.env` 要用 `up -d` 重建容器，`restart` 不会读到新值。`.env` 里有密钥，不要提交到任何仓库。
- **不用 Docker、单机运行**（见 [单机运行](single-host.md)）：执行 `bash scripts/set-dingtalk-credentials.sh`，按提示输入以上四项，Client Secret 输入时不显示。配置写入 `~/.config/cohive/dingtalk.env`，只有你自己能读，并且只在服务进程里加载。然后执行 `scripts/cohive-server.sh restart`。

启动日志里看到下面两行，就表示接通了：

```
钉钉：已启用（Client ID 尾号 …xxxx），Stream 连接中
钉钉：Stream 已连接
```

Cohive 网页“服务器管理 → 设置 → 通讯工具”里能看到钉钉是否在线、离线原因、模板有没有配。

两个模板编号可以先不配：没配通知模板时，群通知照常发，但只写名字、不 @ 人；没配审批模板时，审批消息不带按钮，请到网页“管理 → 待审”处理。先只配凭据看到最基本的通知，再逐步加模板，排查问题更容易。

## 8. 把群绑定到工作空间

1. 用工作空间管理员账号登录 Cohive 网页，进入“管理 → 工作空间”，在“钉钉群”一行点“生成群绑定码”。
2. 网页上会给出一整句 `绑定群 XXXXXXXX`。在钉钉群里 @Cohive，把这句发出去。
3. 机器人回复“已把本群绑定到工作空间 X”，网页上也会自动显示“已绑定：群名”。

绑定码 10 分钟内有效，只能用一次。一个群只能绑一个工作空间；一个工作空间第一期只绑一个群（已绑 Telegram 群的要先解绑）。

也可以手工绑：在群里 @Cohive 发 `群编号`，机器人回复本群编号（`cid` 开头），服务器管理员在服务器上执行 `cohive-server workspace notify --workspace <路径> --dingtalk-chat <群编号>`。

在群里 @Cohive 还可以发：`我是谁`（看自己连接的 Cohive 账号和在本群工作空间里的角色）；发别的内容机器人会回复用法。

## 9. 每位成员连接钉钉

1. 登录 Cohive 网页，进入“个人中心 → 通讯工具”，点“连接钉钉”，网页上会显示一个 8 位绑定码。
2. 在钉钉里打开和机器人 Cohive 的**单聊**：在群里点机器人头像 → 发消息，或在钉钉搜索里搜 `Cohive`。把码发过去（直接发码，或发 `绑定 绑定码`；大小写、中间的空格和连字符都不要紧）。
3. 机器人回复“已收到”。回到网页，页面会显示“机器人收到了钉钉用户 某某 发来的绑定码”，确认是你本人就点“是我，确认连接”；不是你就点“不是我，取消”。确认之后才生效。

注意：码只能**私聊**发给机器人。发到群里的码会立即作废，回网页重新生成一个就行。

## 10. 验收清单

- [ ] 发一张问题单交给某人：群里出现卡片，被 @ 的人收到提醒。
- [ ] 用团队邀请链接注册一个新成员：群里出现审批卡片。管理员点“批准”后，卡片改成“已批准（审批人 …）”。
- [ ] 再来一次，这次在网页“管理 → 待审”里拒绝：群里的卡片同步改成“已拒绝”。
- [ ] 让一位**不是管理员**的成员点审批按钮：提示没有权限，申请不受影响。
- [ ] 把账号绑定码发到群里：提示码已作废（回复里不会出现这个码），网页上这次连接显示失败。
- [ ] 服务器管理 → 设置 → 通讯工具：钉钉显示“在线”。

## 11. 请实测并反馈

这些是文档里没写清楚、只能实测才知道的事。请把结果（截图更好）报到 lee 的 Cohive 工作空间里：

1. 卡片平台能不能导出、导入模板 JSON。
2. 审批按钮能不能按变量 `pending` 隐藏。
3. 通知卡片里 @ 的人有没有收到真正的提醒（还是只看到文字）。
4. 卡片的回调方式要不要在开发者后台另外选“Stream”，还是只要机器人开了 Stream 就行；私有变量 `tip` 能不能只给点击者看。
5. 发布应用时是否要求企业先完成认证。
6. 群里点按钮到卡片改成结果，大概要多久，有没有出现“处理失败”。
7. 你在钉钉开发者后台“资源管理”里看到的接口和 Stream 每月额度是多少，用了多少。
8. 同一张通知卡片在服务重启后会不会重复出现。
9. 机器人单聊在哪里最容易找到（群里点头像，还是搜索）。
10. 群里 @Cohive 后，机器人收到的文字前面带不带“@Cohive”（Cohive 两种都能认，想知道实际是哪种）。
11. Markdown 里的全角符号（Cohive 把用户输入里的 `*`、`_`、`[` 等换成了全角，防止被当成格式）读起来是否别扭。

## 常见问题

- **群里 @Cohive 没有反应**：看第 7 步的启动日志是否显示“Stream 已连接”；确认机器人已加进这个群，并且应用已发布、可见范围包含你。
- **能在群里看到通知，但没有 @ 到人**：被 @ 的人还没连接钉钉（第 9 步），或者通知模板编号没配。
- **审批卡片没有按钮**：审批模板编号没配，或者 Cohive 和钉钉的 Stream 连接当时不在线。此时到网页“管理 → 待审”里处理即可。
- **按钮点了提示失败**：多半是 Stream 掉线或接口额度用完。网页审批不受影响，处理后群里的卡片会同步更新。
- **点了按钮显示“处理中”**：服务器在 1.8 秒内没处理完，结果稍后会改到卡片上；等几秒刷新即可。
- **服务器管理里钉钉一直“离线”**：看离线原因。常见的是凭据错（Client ID、Secret 复制错了）、应用没发布、Stream 推送月度额度用完（钉钉会暂停消息服务），或者服务器出不了外网（要能访问 `api.dingtalk.com` 和钉钉的 WebSocket 网关）。
- **同一个应用能不能给测试和正式两台 Cohive 用**：不能，见第 0 节。
