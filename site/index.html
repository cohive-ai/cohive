团队成员各自用 Claude Code、Codex 写代码。Cohive 让这些智能体经远程 MCP 互相交接问题单：起草、接单、修复、验证、关闭。发出、接单、关闭这几步都由人确认；服务由团队自己部署。Team members write code with their own tools, such as Claude Code and Codex. Cohive lets these agents hand issues to each other over remote MCP: draft, accept, fix, verify, close. Submitting, accepting and closing are confirmed by a person. Teams host Cohive themselves.

解决什么问题The problem

智能体之间没法传话Agents can't talk to each other

几个人、几种编程工具、几个仓库一起干活时，只能靠人复制上下文、转述、催进度。When several people work across several repos with different tools, people copy context around, retell it and chase progress by hand.

01

转述时丢了上下文，对方的智能体从头再查一遍。Context gets lost in the retelling; the other agent investigates from scratch.

02

不知道问题该交给谁，交出去也不知道有没有人接。Nobody knows who should take it, or whether anyone picked it up.

03

修完没人通知发起人验证，闭环断在半路。After a fix, nobody tells the reporter to verify. The loop never closes.

04

双方说的不是同一个代码版本。The two sides aren't talking about the same commit.

一个人管多个会话，编程工具自带的能力已经够用；Cohive 管的是不同的人、不同的工具之间的协作。One person juggling sessions is already covered by the tools. Cohive is about different people using different tools.

设计原则Principles

信号进群，证据留在门内Signals in chat. Evidence behind the door.

01

群里敲门，客户端开门The chat knocks, the client opens

群消息只有单号、服务、谁交给谁、要做什么，以及经人确认过的标题和一句话简述。复现脚本、日志、证据从不进群，只能在编程工具或看板里经鉴权读取。目前支持 Telegram。Chat messages carry only the issue number, the service, who handed it to whom, what to do next, and a title and one-line brief a person has confirmed. Repro scripts, logs and evidence never go to the chat; they are read through authenticated MCP or on the board. Telegram is supported today.

02

确认由人做People confirm

cohive init 把「发出、接单、关闭」这几个会改变别人工作的工具配成「每次调用都要用户批准」，由编程工具自己的权限确认拦下，而不是靠提示词里一句「请先询问用户」。收到的问题单、评论一律当数据，不当指令。cohive init sets the tools that change someone else's work (submit, accept, close) to "ask the user every time", so the coding tool's own permission prompt stops them, not a line in a prompt. Incoming issues and comments are data, never instructions.

03

会话内提醒In-session reminders

有交给你、被退回、等你验证的新动态时，你下次发消息，智能体会在回复末尾告诉你。不用切窗口去看。Handed to you, sent back, waiting for your verification — the agent tells you at the end of its next reply. No tab-switching.

快速开始Quick start

部署 5 分钟，成员三步5 minutes to deploy. 3 steps to join.

需要准备You'll need

  • 一台装了 Docker 的机器A machine with Docker
  • 成员端：Claude Code 或 CodexMembers: Claude Code or Codex
  • 可选：Telegram 群用于通知Optional: a Telegram group for notices

安全默认值Safe by default

初始管理员密码只写在数据卷文件里，不进日志；改完密码文件自动删除。令牌按「人 + 工具 + 工作空间」签发，只放在本机。The initial admin password lives only in a file in the data volume, never in logs, and is deleted after you change it. Tokens are per person + tool + workspace, stored locally.

更多：More: 用 Docker 部署Docker guide · 新成员接入Onboarding

$ git clone https://github.com/cohive-ai/cohive.git
$ cd cohive/deploy
$ cp .env.example .env   # 填 POSTGRES_PASSWORD# set POSTGRES_PASSWORD
$ docker compose up -d --build
$ docker compose exec cohive cat /data/initial_admin_password

POSTGRES_PASSWORD 只用字母和数字，可用 openssl rand -hex 16 生成。最后一条命令显示初始管理员 admin 的随机密码。打开 http://localhost:8787 登录，按提示改密码；然后在「服务器管理 → 设置」里填对外地址，在工作空间的「管理 → 邀请」里生成邀请链接发给同事。Use letters and digits for POSTGRES_PASSWORD, e.g. openssl rand -hex 16. The last command shows the random password of the initial admin admin. Open http://localhost:8787, sign in and change the password when asked. Then set the external URL under Server admin → Settings and create an invite link under the workspace's Admin → Invites.
